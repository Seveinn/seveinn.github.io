# 霞鹜文楷（LXGW WenKai）字体应用流程

本文档整理 HexaLife / WilderBound 项目中「霞鹜文楷」的引入与落地方式，便于在其他 Web / 桌面壳（Tauri、WebView2 启动器等）项目中按同一流程复用。

> 正名：**霞鹜文楷**（英文族名 `LXGW WenKai`），开源仓库 [lxgw/LxgwWenKai](https://github.com/lxgw/LxgwWenKai)。口语中易写成「霞鹭文体」，以本仓库 `assets/fonts` 与 CSS 中的正式名称为准。

---

## 1. 总览：五步落地

```
字体文件入仓 → @font-face 注册 → CSS 变量统一引用 → 全局/组件应用 → 配置开关（可选）
```

| 步骤 | 本仓库落点 | 作用 |
|------|------------|------|
| 1. 资源 | `assets/fonts/*.ttf` + `OFL.txt` | 随游戏分发，离线可用 |
| 2. 注册 | `css/modules/variables.css` 的 `@font-face` | 声明族名与字重文件 |
| 3. Token | `:root { --font-sans: ... }` | 全项目只改一处即可换字体栈 |
| 4. 应用 | `html` / `body` / 组件 `font-family: var(--font-sans)` | 真正画到界面上 |
| 5. 开关 | `SYSTEM_CONFIG.ui.useLxgwWenkaiDisplayFont` + 根节点 class | 可按发行需求开关（见 §5） |

加载关系（运行时）：

```
index.html
  └─ <link rel="stylesheet" href="css/style.css">
        └─ @import modules/variables.css     ← @font-face + --font-sans
        └─ @import modules/config-night.css  ← body { font-family: var(--font-sans) }
        └─ @import modules/wb-components.css ← html / .wb-btn 等使用 var(--font-sans)
  └─ <script> 系统配置.js → 配置.js
        └─ syncHexalifeLxgwWenkaiDisplayFontClass()
              └─ document.documentElement.classList.toggle('hexalife-lxgw-wenkai-font', ...)
```

## 2. 字体资源准备

### 2.1 目录与文件

本仓库路径：`assets/fonts/`

| 文件 | 用途 | 是否被 CSS 引用 |
|------|------|-----------------|
| `LXGWWenKai-Regular.ttf` | 常规（400） | ✅ |
| `LXGWWenKai-Medium.ttf` | 中等（500） | ✅ |
| `LXGWWenKai-Light.ttf` | 细体（300） | ✅ |
| `LXGWWenKaiMono-*.ttf` | 等宽变体 | ❌ 已入库，当前未挂 `@font-face` |
| `OFL.txt` | SIL Open Font License 1.1 | 合规随包分发 |

体积参考（TTF 全字库较大，约 24–27 MB / 文件）。其他项目若关心首屏体积，可改用官方 **子集 / WOFF2** 发行包，流程不变，只改 `src` 的 `url` 与 `format()`。

### 2.2 合规

- 许可证：**SIL OFL 1.1**，可嵌入软件一并分发，**不可单独售卖字体本身**。
- 建议：字体目录旁保留 `OFL.txt`（或许可证全文），发行包不要剥离。

### 2.3 打包注意

- 开发：相对路径 `../../assets/fonts/...`（相对 `css/modules/variables.css`）。
- 构建 / 启动器：`npm run build` 等流程会把 `assets/` 一并拷到发行目录；Steam / Launcher 侧需保证 `WilderBound/assets/fonts/` 与 CSS 相对关系不变，否则 `@font-face` 的 `url` 会 404，界面回退到 Nunito / 系统字体。

## 3. CSS：注册字体与设计 Token

文件：`css/modules/variables.css`（由 `css/style.css` 最先 `@import`）。

### 3.1 可选：西文 Web 字体

```css
@import url("https://fonts.googleapis.com/css2?family=Nunito:wght@400;700;800&display=swap");
```

作为中文主字体之后的 fallback；桌面离线环境若 Google Fonts 不可达，会自然落到系统无衬线字体。

### 3.2 `@font-face`（核心）

```css
@font-face {
  font-family: "LXGW WenKai";
  src: local("LXGW WenKai"), local("霞鹜文楷"),
       url("../../assets/fonts/LXGWWenKai-Regular.ttf") format("truetype");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}

@font-face {
  font-family: "LXGW WenKai";
  src: local("LXGW WenKai"), local("霞鹜文楷"),
       url("../../assets/fonts/LXGWWenKai-Medium.ttf") format("truetype");
  font-weight: 500;
  font-style: normal;
  font-display: swap;
}

@font-face {
  font-family: "LXGW WenKai";
  src: local("LXGW WenKai"), local("霞鹜文楷"),
       url("../../assets/fonts/LXGWWenKai-Light.ttf") format("truetype");
  font-weight: 300;
  font-style: normal;
  font-display: swap;
}
```

要点：

1. **同一 `font-family` 名**，用不同 `font-weight` 映射不同文件（浏览器按字重选面）。
2. `local(...)` 优先用系统已安装的同名字体，减少重复下载。
3. `font-display: swap`：先显示回退字体，字体就绪后再替换，避免长时间空白字。

### 3.3 CSS 变量（统一入口）

```css
:root {
  --font-sans: "LXGW WenKai", "Nunito", system-ui, -apple-system, "Segoe UI", sans-serif;
}

/* 可选：根节点 class 再次锁定同一栈（见 §5） */
html.hexalife-lxgw-wenkai-font {
  --font-sans: "LXGW WenKai", "Nunito", system-ui, -apple-system, "Segoe UI", sans-serif;
}
```

业务与组件样式**不要写死** `"LXGW WenKai"`，一律写：

```css
font-family: var(--font-sans);
/* 或带兜底 */
font-family: var(--font-sans, system-ui, sans-serif);
```

## 4. 应用到界面

### 4.1 全局

| 位置 | 写法 |
|------|------|
| `css/modules/wb-components.css` | `html { font-family: var(--font-sans); }` |
| `css/modules/config-night.css` | `body { font-family: var(--font-sans, "Nunito", sans-serif); }` |

子元素多数 `inherit` 或再写 `var(--font-sans)`（如 `.wb-btn`、指南气泡、仓库等）。

### 4.2 组件层约定

- 新面板 / 按钮：优先 `font-family: var(--font-sans)` 或 `inherit`。
- 需要等宽（代码、Debug）时**显式覆盖**，例如设置面板：`"Consolas", "Monaco", monospace`，不要误用文楷。
- Canvas 内自绘文字若要用同一字体，需在绘制侧 `ctx.font = '... LXGW WenKai ...'` 并确认 `@font-face` 已加载（本流程文档以 DOM/CSS UI 为主）。

### 4.3 HTML 入口

`index.html` 只需引入总样式表即可，**不必**再单独写 `<link>` 指向字体文件：

```html
<link rel="stylesheet" href="css/style.css" />
```

## 5. 配置开关（可选能力）

### 5.1 配置项

`js/config/系统配置.js`：

```js
ui: {
  /** 是否使用随游戏分发的「霞鹜文楷」作为界面主字体 */
  useLxgwWenkaiDisplayFont: true,
  // ...
}
```

经 `js/config/配置.js` 浅合并进全局 `CONFIG`。

### 5.2 运行时同步 class

`js/config/配置.js`（在配置合并之后立刻执行）：

```js
function syncHexalifeLxgwWenkaiDisplayFontClass() {
  if (typeof document === 'undefined' || !document.documentElement) return;
  const enabled = !!(CONFIG && CONFIG.ui && CONFIG.ui.useLxgwWenkaiDisplayFont === true);
  document.documentElement.classList.toggle('hexalife-lxgw-wenkai-font', enabled);
}
syncHexalifeLxgwWenkaiDisplayFontClass();
window.syncHexalifeLxgwWenkaiDisplayFontClass = syncHexalifeLxgwWenkaiDisplayFontClass;
```

脚本顺序要求：`系统配置.js` →（其他配置）→ `配置.js`，保证读到已合并的 `CONFIG.ui`。

### 5.3 当前实现说明（迁移时注意）

本仓库现状：

- `:root` 的 `--font-sans` **已经包含** `"LXGW WenKai"`；
- `html.hexalife-lxgw-wenkai-font` 设置的是**同一套**字体栈。

因此：把 `useLxgwWenkaiDisplayFont` 设为 `false` 只会去掉 class，**并不会**从 `:root` 去掉文楷名。若其他项目需要「真正可关」：

**【推荐做法】** `:root` 使用不含文楷的回退栈；仅在启用 class 时写入文楷：

```css
:root {
  --font-sans: "Nunito", system-ui, -apple-system, "Segoe UI", sans-serif;
}
html.your-project-wenkai-font {
  --font-sans: "LXGW WenKai", "Nunito", system-ui, -apple-system, "Segoe UI", sans-serif;
}
```

不需要开关时，可省略 JS，只在 `:root` 写死文楷栈即可。

## 6. 其他项目最小复刻清单

按顺序打勾即可复现本流程：

1. **下载字体**（Regular / Medium / Light，按需）放入 `assets/fonts/`，附带 `OFL.txt`。
2. **在最早加载的 CSS** 中写三组 `@font-face`（族名统一为 `"LXGW WenKai"`）。
3. **定义** `--font-sans: "LXGW WenKai", <西文回退>, system-ui, sans-serif;`
4. **在 `html` 或 `body`** 设置 `font-family: var(--font-sans);`
5. **组件样式**一律引用 `var(--font-sans)`，禁止散落硬编码字体名（特殊用途除外）。
6. **确认相对路径**：从 CSS 文件到 `assets/fonts` 在开发与发行目录下都正确。
7. （可选）配置布尔开关 + 根节点 class，且让「关」时 `:root` 不含该字体名。
8. （可选）等宽变体另加 `@font-face` + `--font-mono`，仅用于代码区。

### 6.1 极简模板（无配置开关）

```css
/* fonts.css —— 在入口 CSS 最前引入 */
@font-face {
  font-family: "LXGW WenKai";
  src: url("/assets/fonts/LXGWWenKai-Regular.ttf") format("truetype");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}
@font-face {
  font-family: "LXGW WenKai";
  src: url("/assets/fonts/LXGWWenKai-Medium.ttf") format("truetype");
  font-weight: 500;
  font-style: normal;
  font-display: swap;
}
@font-face {
  font-family: "LXGW WenKai";
  src: url("/assets/fonts/LXGWWenKai-Light.ttf") format("truetype");
  font-weight: 300;
  font-style: normal;
  font-display: swap;
}

:root {
  --font-sans: "LXGW WenKai", system-ui, -apple-system, "Segoe UI", sans-serif;
}

html, body {
  font-family: var(--font-sans);
}
```

路径请按你项目的静态资源根目录调整（绝对路径 `/assets/...` 或相对路径均可）。

## 7. 验收与排错

| 检查项 | 期望 |
|--------|------|
| DevTools → Network | 出现 `LXGWWenKai-*.ttf`（或本机已 `local()` 命中则可能不请求） |
| 计算样式 | `html`/`body` 的 `font-family` 含 `LXGW WenKai` |
| 字重 | `font-weight: 300/400/500` 时对应不同文件，而非伪斜/伪粗糊成一团 |
| 离线 / Steam 包 | 断网启动仍显示文楷（不依赖 Google Fonts） |
| 体积 | 全量 TTF 较大；若首包过大，换 WOFF2 子集并改 `format("woff2")` |

常见失败原因：

1. CSS 相对路径在打包后错位（最常见）。
2. 组件写死了 `Nunito` / `Arial`，覆盖了变量。
3. Canvas / 第三方 iframe 未走同一套 `@font-face`。
4. 仅拷了 Regular，却大量使用 700，浏览器合成粗体观感变差（可再引入 Bold 面，或限制 UI 字重到 300–500）。

## 9. 设计侧补充（字号层级）

与 WilderBound UI 规范对齐时的建议（实现仍靠 CSS，与字体引入无关）：

| 层级 | 建议规格 | 场景 |
|------|----------|------|
| H1 | 28–32px / 700 | 开始界面主文案 |
| H2 | 20–24px / 600 | 面板副标题 |
| H3 | 16–18px / 700 | 区块标题 |
| 按钮 | 16–18px / 700 | 主操作 |
| 正文 | 14–16px / 400–500 | 说明、列表 |
| 辅助 | 11–12px / 400 | 版本号、元数据 |

当前已注册字重为 **300 / 400 / 500**；若规范大量使用 700，需额外引入 Bold 文件并增加对应 `@font-face`，或把组件字重下调到已有面。
