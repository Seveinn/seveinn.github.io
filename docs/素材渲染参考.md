# 素材绘制与渲染参考

本文档整理自 `salad_plate.png` 显示发糊问题的排查与优化过程，供后续制作、导入和调试游戏素材时使用。

相关代码：

| 模块 | 文件 |
|------|------|
| 设计尺寸与渲染常量 | `js/config/constants.js` |
| Canvas 缩放与 DPR | `js/modules/input.js` → `resize()` |
| 绘制逻辑 | `js/modules/render.js` |
| 素材配置与预加载 | `js/config/game-data.js`、`js/modules/environment.js` |

---

## 1. 渲染架构概览

### 1.1 坐标系

- **设计分辨率（逻辑像素）**：390 × 780（`DESIGN_W` / `DESIGN_H`）
- 游戏内所有坐标、家具尺寸、`drawImage` 目标宽高均使用逻辑像素
- 触摸输入通过 `screenToGame()` 映射到同一坐标系

### 1.2 Canvas 与 HiDPI

`resize()` 将 Canvas **内部分辨率** 按设备像素比放大，再通过 `setTransform` 保持绘制仍用逻辑坐标：

```
canvas.width  = DESIGN_W × min(devicePixelRatio, MAX_DPR)
canvas.height = DESIGN_H × min(devicePixelRatio, MAX_DPR)
ctx.setTransform(dpr, 0, 0, dpr, 0, 0)
```

CSS 仍将 Canvas 拉伸至全屏（`100vw × 100vh`），但不再依赖浏览器对低分辨率位图的二次放大。

当前常量（`constants.js`）：

| 常量 | 默认值 | 含义 |
|------|--------|------|
| `MAX_DPR` | `3` | 像素比上限，防止超高 DPR 设备内存过大 |
| `FOOD_ASSET_DRAW_SCALE` | `2` | 食物类 PNG 绘制宽度 = `fontSize × 此值` |

### 1.3 渲染链路示意

```
PNG 源文件（naturalWidth × naturalHeight）
        ↓
  drawImage 缩放到目标逻辑尺寸（render.js）
        ↓
  390×780 逻辑画布（实际 buffer = 390×DPR）
        ↓
  CSS 全屏显示（不再二次放大模糊）
        ↓
  屏幕物理像素
```

## 2. 案例：高清素材为何看起来发糊

以 `assets/salad_plate.png` 为例：源图分辨率较高、线条清晰，但在游戏中显得「肉、糊」。

**优化前**的完整链路存在 **三重损失**：

1. **Canvas 无 DPR 适配**：内部分辨率仅 390×780，在 DPR=3 的手机上被浏览器放大约 3 倍 → 全局发软
2. **运行时大幅缩小**：装盘图绘制宽度仅 `fontSize × 1.5`（约 27～39 逻辑像素），相对 512px+ 源图缩小 10～20 倍
3. **默认双线性插值**：`imageSmoothingEnabled` 为 `true`，缩小时细线（叶脉、盘沿）被平滑抹掉

背景图铺满 390×780、家具宽约 72～90px，缩小倍率小得多，因此同类高清素材在 **小图标场景** 下更容易暴露问题。

---

## 3. 模糊成因对照

| 因素 | 表现 | 影响范围 |
|------|------|----------|
| 无 HiDPI，Canvas 被 CSS 放大 | 整屏边缘发软 | 全局 |
| 高清 PNG → 极小 `drawImage` 目标尺寸 | 细线、盘沿丢失 | 装盘/手持/小图标 |
| 默认 `imageSmoothingEnabled` | 缩小时过度平滑 | 所有缩放绘制 |
| 源图细节过多、显示面积过小 | 矢量风细线最先糊 | 叶脉、刀锋、盘沿等 |
| 源图远大于实际需要 | 浪费带宽与 CPU，且运行时缩放质量差 | 性能 + 清晰度 |

## 4. 已实施的优化（2025-06）

### 4.1 Canvas HiDPI 适配

**文件**：`js/modules/input.js`

```javascript
const dpr = Math.min(window.devicePixelRatio || 1, MAX_DPR);
this.canvas.width = Math.round(DESIGN_W * dpr);
this.canvas.height = Math.round(DESIGN_H * dpr);
this.ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
this.ctx.imageSmoothingEnabled = true;
this.ctx.imageSmoothingQuality = 'high';
```

### 4.2 提高食物类素材绘制倍率

**文件**：`js/config/constants.js`、`js/modules/render.js`

- `FOOD_ASSET_DRAW_SCALE`：`1.5` → `2`
- 统一通过 `getFoodAssetDrawSize(fontSize)` 计算宽度
- 菜板/灶台「待取餐」图标：固定尺寸 `34` → `44` 逻辑像素

### 4.3 优化效果（逻辑像素 → DPR=3 物理像素）

| 场景 | fontSize | 优化前宽度 | 优化后宽度 | DPR=3 约物理宽 |
|------|----------|------------|------------|----------------|
| 餐桌装盘 | 20 | 30px | 40px | ~120px |
| 玩家手持 | 26 | 39px | 52px | ~156px |
| 店员手持 | 22 | 33px | 44px | ~132px |
| 备菜台/冰箱 | 18 | 27px | 36px | ~108px |
| 站点待取餐 | — | 34px | 44px | ~132px |

## 5. 素材规格建议

### 5.1 核心原则

> **按「游戏中的实际显示尺寸 × MAX_DPR」导出 PNG，而不是盲目追求超大分辨率。**

运行时从 1024px 缩到 40px，不如直接提供约 120px（40 × 3）的源图清晰，且更省内存与 CPU。

### 5.2 推荐导出尺寸

以下「建议源图宽度」= 逻辑绘制宽 × `MAX_DPR`（当前为 3）。高度按素材宽高比等比计算。

| 素材类型 | 配置位置 | 逻辑绘制宽（约） | 建议源图宽（约） | 备注 |
|----------|----------|------------------|------------------|------|
| 全屏背景 | `BG_ASSET_SRC` | 390 | **390～1170** | 可 1× 全屏或 2×/3×；有离屏缓存 |
| 餐桌 / 椅子 | `TABLE/CHAIR_ASSET_SRC` | 72×1.2 ≈ 86 | **260～280** | 按家具 `w` 与 `scale` |
| 菜板 / 灶台 | `BOARD_*` / `STOVE_*` | 82～90 | **250～270** | 宽 = 家具 `w` |
| 切菜刀 | `KNIFE_ASSET_SRC` | ~43（板宽×0.52） | **130～150** | |
| 储物箱本体 | `MATBOX_ASSETS` | 72 | **220** | |
| 装盘菜品 | `PLATED_DISHES` | 36～52 | **110～160** | 随场景 fontSize 变化 |
| 站点成品 | `STATION_READY_ASSETS` | 44 | **130** | |
| 手持食材 | `INGREDIENT_ASSETS` | 40～52 | **120～160** | 储物箱内 40，手持 52 |

### 5.3 美术与格式

- **格式**：PNG，保留透明通道（`RGBA`）
- **风格**：矢量风细线素材对小尺寸更敏感；若长期以图标尺寸展示，导出前可在目标尺寸下目视检查
- **避免**：无意义的 2K/4K 单张图标；JPEG 压缩；非整数缩放比（如源图 1000px 显示 37px）
- **可选**：对固定尺寸元素做离线预缩放（导出 @1x/@2x/@3x 三套），运行时不再大幅缩放

## 6. 游戏内绘制尺寸速查

### 6.1 家具与场景元素（逻辑像素）

| 元素 | 宽度来源 | 典型逻辑宽 |
|------|----------|------------|
| 餐桌 | `table.w × 1.2` | ~86 |
| 椅子 | 按椅子布局 | ~40 |
| 菜板 | `board.w` | 82 |
| 石头篝火 | `stove.w` | 90 |
| 储物箱 | `matbox.w` | 72 |
| 背景 | 固定 | 390 × 780 |

家具规格定义：`js/modules/furniture.js` → `addFurniture()` → `specs`。

### 6.2 食物与物品图标

绘制入口：`drawFoodItemIcon()`、`drawTableFoodItem()`、`drawFoodItemImage()`。

```
绘制宽度 = fontSize × FOOD_ASSET_DRAW_SCALE   // 当前 FOOD_ASSET_DRAW_SCALE = 2
绘制高度 = 宽度 × (img.naturalHeight / img.naturalWidth)
```

各调用点 `fontSize`：

| 调用场景 | fontSize |
|----------|----------|
| 餐桌上的菜 | 20 |
| 玩家头顶手持 | 26 |
| 店员头顶手持 | 22 |
| 备菜台 / 冰箱格子 | 18 |
| 储物箱内食材（固定） | 40（未走 fontSize 倍率） |
| 站点待取餐（固定） | 44 |

### 6.3 素材配置与预加载

在 `game-data.js` 中声明路径：

```javascript
PLATED_DISHES      // 装盘图 → platedImages
STATION_READY_ASSETS // 站点成品 → stationReadyImages
INGREDIENT_ASSETS  // 食材 → ingredientImages
MATBOX_ASSETS      // 储物箱外观 → matboxImages
```

在 `constants.js` 中声明场景/家具路径，于 `environment.js` → `initEnvironment()` 预加载。

渲染时统一走 `drawImageAsset()`，加载未完成时 `isAssetReady()` 返回 false，回退 emoji 或程序绘制。

## 7. 新增素材流程清单

1. **确定显示场景** → 查上表得到逻辑绘制宽
2. **计算源图尺寸** → 逻辑宽 × `MAX_DPR`（必要时 +10% 余量）
3. **导出 PNG** → 放入 `assets/`，命名与现有风格一致
4. **注册路径** → `game-data.js` 或 `constants.js`
5. **预加载** → 若为新 Map 类型，在 `environment.js` 的 `initEnvironment()` 增加加载循环
6. **绘制** → 优先复用 `drawFoodItemImage` / `drawImageAsset`；家具类按 `家具.w` 等比绘制
7. **真机验证** → 在 DPR=2、3 设备上查看；仍糊则加大绘制尺寸或换合适源图，而非继续增大 PNG

## 8. 调参指南

| 现象 | 建议调整 |
|------|----------|
| 整屏偏糊 | 检查 `resize()` 是否生效；确认 `MAX_DPR` 未过小 |
| 仅小图标糊 | 增大 `FOOD_ASSET_DRAW_SCALE`（如 `2.5`）或提高对应 `fontSize` |
| 单张家具糊 | 检查源图相对 `家具.w × MAX_DPR` 是否过大或过小 |
| 内存占用高 | 降低 `MAX_DPR` 或缩小源图分辨率 |
| 边缘锯齿 | 保持 `imageSmoothingQuality = 'high'`；检查是否过度缩小 |

修改 `FOOD_ASSET_DRAW_SCALE` 后，同步检查 `getFoodItemDrawHeight()` 与布局（如餐桌上菜品占位）是否仍合理。

## 9. 已知限制

### 9.1 背景离屏缓存

`environment.js` 中 `bgCacheCanvas` 固定为 **390×780**（无 DPR 倍率）。主 Canvas 已 HiDPI，背景缓存绘制到主画布时仍会经历一次放大。若背景在超高 DPR 下仍略软，可将缓存尺寸改为 `DESIGN_W × dpr`（需与 `resize()` 联动重建缓存）。

### 9.2 CSS 全屏拉伸

Canvas 逻辑比例 390:780 与部分设备 viewport 比例不完全一致时，会有轻微非等比拉伸。一般可忽略；若需严格等比，需改 `#game-wrap` 布局策略。

### 9.3 resize 重置上下文

设置 `canvas.width/height` 会重置 Canvas 上下文状态，因此 **每次 `resize()` 都必须重新** `setTransform` 与 smoothing 配置。

## 10. 排查流程（素材发糊时）

```
1. 在浏览器 DevTools 查看 canvas.width / devicePixelRatio
      ↓ 若 canvas.width === 390 → HiDPI 未生效
2. 打印 img.naturalWidth 与 drawImage 目标 w/h
      ↓ 若 naturalWidth / w > 4 → 源图过大或绘制过小
3. 对比同屏背景/家具与小图标
      ↓ 仅小图糊 → 提高 FOOD_ASSET_DRAW_SCALE 或换小尺寸源图
4. 导出目标尺寸的 PNG 离线对比
      ↓ 离线清晰、线上糊 → 运行时缩放问题
      ↓ 离线也糊 → 美术导出尺寸/线宽问题
```
